Fetch claims

Downloads payer and provider claim bundles from client S3 into a local folder, extracts the eight structured datasets, and (optionally) loads them into Redshift. Claims are selected from {{ source_table }}. The destination folder is itself a review root - each claim lands in its own subfolder - so a finished fetch hands straight over to processing.

Which claims

Most recent first, by last_insert_dt. Enter a number, or all / none / false for no cap.

One per line, or comma-separated. Full case IDs (PMJAY/UK/S/2026/R4/2026070810062219) are trimmed to the trailing ID.

Uses a registration_id column if present, otherwise the first column. Merged with anything pasted above.

Filters

Off: only policy_code LIKE 'PMJAY%' claims are selected.

Filters on hospital_type. Default applies no condition at all.

A claim's procedure_code holds its whole procedure list, pipe-delimited, so both readings are possible:
MG110|ABC23 — claims with either code (alternatives)
MG110,ABC23 — claims with both codes (all required)
MG110|ABC23,LB001 — (MG110 or ABC23) and LB001
Each code must match a whole item in that list, so LB05 will not match LB055; write LB.* if you do want a prefix. Empty = no filter.

Same syntax, applied as a rejection: A|B drops claims containing either, A,B drops only claims containing both. Pre-filled with {{ default_exclude_codes }}, which this pipeline has always excluded; clear the box to exclude nothing.

Destination and output

Bundles land here as <folder>/<registration_id>/{payer,provider}. Re-fetching a claim replaces its folder in place. Files are never deleted by a fetch started here - they are what the review side displays.

    Writes the eight claim_bundle_* tables, replacing any existing rows for the same claims. Untick for a files-only pull that touches nothing in the warehouse.

    The XLSX report reads the loaded rows, so it is skipped when the Redshift load is off.
